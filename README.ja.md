# xbookmarkshelf

[English](README.md) | 日本語

![検索・フィルタ・マークを備えたブックマーク一覧](assets/screenshots/bookmarks.png)

Xのブックマークやいいねを整理して読むためのビューアーです。自分で作ったマークでジャンル分けし、検索やフィルタで投稿を探せます。Chrome拡張版と、手元のJSONを開くローカル管理版があります。

Windows版Chrome向けのv0.1.3です。

## Chrome拡張版の使い方

ビルド済みの拡張はChrome 120以上で使えます。Node.js・npmのインストールやサーバーの起動は不要です。

Chromeウェブストア版は、Chromeの更新機能で更新されます。GitHub ReleasesのZIPを使う場合は、以下の手順で読み込んでください。

1. 拡張の配布ZIPを展開します。
2. Chromeで `chrome://extensions` を開き、開発者モードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」から、展開したフォルダ（manifest.jsonがあるフォルダ）を選びます。

更新時は同じフォルダのファイルを差し替え、拡張機能・X・ライブラリを再読み込みします。データを引き継ぐには、同じ拡張IDとChromeプロファイルを使ってください。

## ブックマーク・いいねを取り込む

取り込みはXの画面に表示された内容（DOM）を読み取る方式です。利用は自己責任でお願いします。

1. Xへログインし、[History](https://x.com/i/history) でBookmarksかLikesを開きます。従来のブックマーク画面や、自分のプロフィールのいいね画面にも対応しています。
2. 拡張アイコンを押し、取り込み対象・範囲・待機方法・今回の上限を確認します。
3. 「少量ずつ自動取り込み」を押し、Xのタブを表示したまま待ちます。

最大10件ずつ保存します。初期設定は固定3秒・1回100件まで。待機は固定または最短〜最長の間でランダムに選べます（3〜30秒）。最短3秒はXへの負荷を抑えるための設定です。上限は10〜1,000件で、取り込み条件は次回へ引き継ぎます。

ブックマーク・いいねの取得先URLは「設定 → 取得先URL」で変更・保存でき、「初期URLに戻す」で元に戻せます。HTTPSの `x.com` のみ対応し、通常は変更不要です。URLだけの変更には設定で対応できますが、画面構造も変わった場合は拡張の更新が必要です。

取り込み範囲の既定は「現在の表示位置から取り込む」です。Xで希望する位置までスクロールしてから拡張を開くと、画面内に見えている投稿から下へ進みます。「新規分を中心に取得」は先頭から始め、保存済み投稿が30件続くと終了します。今回の上限は新規・既存の両方を数えます。一時停止後も、次の実行では選択した範囲とその時点のX画面の位置を使い、前回の位置を自動復元しません。

ポップアップを閉じても取り込みは続き、再実行では重複を除きます。Xタブの非表示、ページ移動、取得制限などで停止します。全件取得や完全同期は保証しません。

## ライブラリで探す・仕分ける

「ライブラリを開く」から管理画面へ進みます。ロゴ下でブックマーク／いいねを切り替え、投稿・マーク・既読を別々に管理できます。表示設定は共通です。

- 本文検索と、投稿者・アカウント・マーク・既読・メディア・本文URL・投稿日などのフィルタ。投稿者欄は `@ID` でIDの完全一致、`@` なしで投稿者名・IDの部分一致。
- 名前とアイコンを選べるマークをアカウントごとに30個まで登録。複数付与でき、1投稿のマークとタグは合計20個まで。
- 投稿のアイコンでマークを付与・解除。収まらないマークは「…」から選び、管理ページで順番を変更。
- 本文を開くと既読になり、「あとで読む」から外れます。「マークなし」ではマークの付いていない投稿を確認できます。
- 保存順に加え、投稿日が新しい順／古い順を選択。投稿日不明の投稿は、投稿日順では末尾に表示。
- 連続スクロール、カード／リスト表示、1〜5列、ライト／ダーク、日本語／英語に対応。初期設定ではブラウザの言語に従います。

## LM Studioで自動マークを付ける

任意の追加機能です。画像対応のdecision model（d1-3B等）をロードした、ローカルのLM Studioサーバーが必要です。通常の閲覧・手動マークにはサーバーは不要です。

1. 設定画面の一番下にある「ローカルAIで自動マーク」でURLとモデルID（既定は `http://127.0.0.1:1234` と `d1-3b`）、マークを付ける基準を入力します。拡張では「接続を確認して保存」、ローカル管理版では「接続を確認して適用」を押します。拡張は接続先と、画像利用を選んだ場合はXの画像へのアクセス権限を求めます。ローカルHTMLではLM StudioのServer Settingsで **Enable CORS** を有効にする必要があります。
2. 分類内容が分かる名前でマークを作成します。既定は確率80%以上のマークをすべて追加します。該当なしは変更せず、既存マークも保持します。
3. 拡張のPopupで「取り込み中に自動マークを付ける」を選んで開始します。オン・オフは他の取り込み条件と一緒に保存され、Popupを開き直しても前回の選択を戻します。AI接続設定がない間はチェックを無効にしてAIへ送信せず、再接続後に記憶した選択を戻します。Popupを開くだけでは取り込みや分類を開始しません。Popupと取り込み画面には今回の進捗・結果・失敗メッセージと分類中の停止操作を表示し、取り込み後の手動開始・再試行ボタンは置きません。保存した投稿を手動で判定する場合は、サイドバーの「マークなし」の下にある「自動マーク」ページで対象アカウントと件数を確認して「このアカウント範囲を自動マーク」を押します。取り込みと分類は別に動き、Popupを閉じても分類は続きます。
4. ローカル管理版では、一覧で検索・絞り込みを行ってから「自動マーク」ページを開き、対象件数を確認して「検索結果を自動マーク」を押します。ページを移動しても分類は続き、処理中はサイドバーに表示します。結果を「保存」で管理JSONへ反映してください。HTMLを閉じるか再読み込みするとAIの接続設定はリセットされるため、次回は接続し直してください。

「画像も判定に使う」をオンにすると、一覧の画像プレビューがオフでもAIは画像を使って判定します。保存済みの投稿画像・引用画像・動画表紙等から1投稿につき最大4枚をXの画像サーバー（pbs.twimg.com）で読み込み、一時的なJPEGプレビューをLM Studioへ渡します。like.jsなど画像情報のない投稿は本文だけで判定します。ブラウザーから画像を取得できない投稿は失敗として表示し、画像利用をオフにすると本文だけで再実行できます。画像本体はバックアップへ含めません。

分類条件にはマーク名を使います。確率による判定にも誤りがあるため、用途に合わせて基準を調整してください。停止しても反映済みのマークは残ります。拡張は進捗を記録し、Workerが停止した場合も未処理分を再開します。推論中に削除・編集された投稿は保留します。接続先はHTTPのlocalhostまたは127.0.0.1に限定し、APIトークンやクラウド接続には対応しません。

分類が連続3件失敗した場合は自動停止します。反映済みのマークは残り、設定確認後に再実行できます。

## 画像・動画・リンクカード

拡張版の画像プレビューは初期設定でオンです。ローカル管理版はオフから始まり、切り替えた状態を記憶します。オンの場合は、保存した参照URLから画像を読み込みます。両版とも写真のクリックで拡大でき、複数画像は切り替えられます。動画は表紙と元投稿へのリンクを表示します。Xに表示されたリンクカードや引用も保存します。

画像の読み込み先は `https://pbs.twimg.com` に限ります。画像・動画をダウンロードして保存する機能はありません。オフラインやURLの失効で画像を表示できない場合があります。

## バックアップとデータ削除

投稿と表示設定は別のJSONファイルで保管します。

| ファイル | 内容・操作場所 |
| --- | --- |
| 投稿バックアップ | 投稿、既読、マーク・タグ、メディア参照。バックアップ画面で全件または1つのマークを選択 |
| 設定ファイル | 言語、テーマ、列数、表示形式、画像プレビュー。設定画面で書き出し・取り込み |

投稿バックアップのファイル名は、ブックマークが `xbookmarkshelf-bookmarks-…json`、いいねが `xbookmarkshelf-likes-…json` です。以前の `posts` 名のJSONも取り込めます。

投稿バックアップは1ファイル20MiB、設定ファイルは64KiBまで取り込めます。投稿バックアップに表示設定や取り込み履歴は含みません。ブックマークといいねは、書き出した側へ復元してください。再取り込みでは既存の既読・分類を保ちます。

大きなバックアップは自動で分割します。すべてのファイルを保存し、復元・ローカル管理版への追加ではまとめて選んでください。

一覧から選択した投稿を削除でき、設定から選択中の側の投稿を全削除できます。設定では件数と使用容量の概算も確認できます。マーク・タグの定義、設定とX側のブックマーク・いいねは保持します。削除前にバックアップを取り、分割された場合は全ファイルの保存を確認してください。

## ローカル管理版の使い方

配布ファイルの `xbookmarkshelf-local.html` をデスクトップ版Chromeで開きます。HTMLはアプリ本体、管理JSONは投稿データの保存先です。拡張やサーバーは不要で、投稿は手元の管理JSONに保存します。

1. 「新しく作る」か「管理JSONを開く」で始めます。
2. 「追加取り込み」で、X API v2のJSON、Xアーカイブの `data/like.js`、拡張の投稿バックアップ、管理JSONを選びます。複数ファイルを選べます。分割バックアップは全ファイルをまとめて選びます。
3. 拡張版と同じように検索・仕分けし、「保存」で管理JSONを書き出します。取り込みや編集の後も保存してください。
4. 次回は前回の管理JSONから再開できます。権限が切れた場合は「開く」を押してください。

X API v2のJSONは、`data`配列を含む投稿一覧のレスポンスに対応します。取り込み画面で「ブックマーク／いいね」と保存するアカウントを選びます。既存のアカウントを選ぶか、自分のXユーザー名を入力して追加してください。投稿者の名前とは別です。同じ取得先の複数ページをまとめて選べ、件数を確認してから取り込みます。別のアカウントやブックマーク／いいねのJSONは、取り込みを分けてください。

APIキーの入力やXへの接続は不要です。本文・投稿者・投稿日・画像や動画の表紙・引用は、JSONに含まれる情報だけを使います。ブックマークには投稿者のユーザー名が必要なため、`author_id`と`includes.users`（`username`）を含むJSONを使ってください。画像には`attachments.media_keys`と`includes.media`が必要です。取得できていない情報や続きのページは自動取得しません。既存のマーク・タグ・既読状態・表示設定は保持します。like.js由来の投稿へ情報を補う場合は「いいねアーカイブ」を選びます。

合計20万件・管理JSON 512MiBまで扱えます。追加元のAPI JSON・like.js・投稿バックアップは各20MiB・5万投稿まで、一度に選ぶファイルは合計512MiBまでです。開いている間はメモリを使います。ブラウザに記憶するのはファイルへの参照と画像プレビュー設定だけです。

全体・ブックマーク／いいね・マークごとのバックアップに対応し、ブックマークは拡張へ戻せる投稿JSONでも出力できます。表示設定は管理JSONに含まれます。並び順はファイル順／逆順に加え、拡張と同じ投稿日順も選べます。

like.jsにない投稿者・画像などは自動取得しません。投稿IDから計算した投稿日は、いいねした日時とは区別します。複数のlike.jsは1つの区分へ統合します。

保存に失敗しても未保存の変更は保持します。再試行か別名保存で保管し、同じ管理JSONの同時編集は避けてください。直接保存に対応しないブラウザではJSONをダウンロードできます。
