# xbookmarkshelf

Xのブックマークを少量ずつ読み取り、Chrome内で検索・閲覧するローカルファーストの拡張です。**現在はv0.3.9プロトタイプ。** Windows版Chromeが対象です。利用者は100件取り込み・再試行の重複防止・英字検索・画像ONを確認済み。Windows実機と実Xの取得範囲/欠損/異常系は未確認です。

サイドバーの保存先表示は「データはブラウザ内に保存」です。静的レビューで見つかった可用性の指摘2件はv0.3.7で修正し、合成入力で回帰検証しています。製品全体の侵入試験やWindows実機での網羅確認は未実施です。

## 今できること

- 最大10件ずつ読み取り、メディアの読み込みを待って保存し、保存確認後に少しスクロールする。
- 初期設定は3秒待機・1回100件まで。待機3〜30秒、上限10〜1,000件に変更できる。
- 一時停止・終了・先頭からの再実行。保存済み投稿を保持し、再取得の重複を除く。
- 新規分中心のモードでは既知の投稿が30件続いたら推定終了する。
- サイドバー、検索バー、カード/リスト一覧、ライト/ダーク表示。設定から日本語/Englishを切り替え、開いているライブラリとPopupに反映。
- 本文検索に投稿者、アカウント、マーク/タグ、メディア有無/画像/動画、既読、本文URL有無、投稿日を組み合わせて絞り込む。保存日時順、50件ページ、1〜5列。
- 本文クリックで詳細を開いて既読にする。URLは詳細でクリックでき、登録済みタグは候補から選択して保存できる。
- 名前付きマークをアカウントごとに30個まで登録し、投稿のアイコンをワンクリックで付与・解除。複数マーク、サイドバーのマーク別ページ、名前/アイコンの変更、既存タグのマーク化。
- Xに表示されたリンクカードのサムネイルURL・タイトルを保存し、一覧と詳細に表示。画像プレビューがオンのときだけ画像を読み込む。
- ダーク設定を描画前に反映し、リロード時の白い画面を抑える。
- 既読・投稿ごとのタグ編集。画像プレビューは設定でオンにできる（既定オフ）。
- 全件、または1つのマークに絞ったJSON v2バックアップと復元。旧v1も読み込める。既存ユーザー状態/マーク設定を優先し、タグ関連を統合する。
- 一覧の「投稿を選択」から、このページの投稿を選んで削除。設定の「投稿データの管理」から全アカウントの投稿を全削除し、保存件数と使用容量の概算を確認。削除前に件数を確認し、JSONバックアップを保存できる。マーク・タグ定義と表示設定は保持。
- 設定画面から言語・テーマ・列数・カード/リスト・画像プレビューだけのJSONをエクスポート。内容を確認してインポートできる。投稿用と設定用のファイルを分ける。

複数画像は矢印で切り替え、クリックで大きく見られます。動画は表紙を表示し、「Xで動画を見る」で元投稿を開く。動画本体は保存しません。独立したタグページはマークに集約し、既存タグの編集・フィルタは保持しています。以前の取り込みで抜けたURL・リンクカード・メディアは、再取り込みで補完できます。サムネイルはXの表示DOMとpbs.twimg.comの参照に限り、画像本体は保存しません。投稿の重複追加とユーザー状態の上書きは行いません。

全件取得・完全同期は保証しません。本文は画面で確認できた範囲を保存し、メディアはURL参照のみです。ハッシュタグ条件、複数タグのAND/OR、保存済み検索、一括タグ付け、CSV/Markdown、性能検証は後続タスクです。

設定の「言語」は未設定なら「システムに従う」です。Chromeの表示言語が日本語なら日本語、それ以外なら英語で表示します。日本語/Englishの固定指定もでき、保存済みの指定は保持します。再読込後も保持し、投稿本文や自分で付けた分類名は変更しません。言語なしの旧設定JSONも読み込めます。v0.3.4以下は5キー設定JSONを、v0.3.5はlanguageがsystemの設定JSONを拒否するため、新版で復元してください。

バックアップ画面の「バックアップ対象」でマークを選ぶと、対象件数を確認して、そのマークが付いた投稿だけを書き出せます。他のマーク・タグ・既読・メディア参照も対象投稿の分を含み、通常のJSON復元で読み込めます。全件バックアップも継続します。

## マークで仕分ける

サイドバー下段の「マーク＋」見出しから、名前とアイコンを登録します。既存タグを選んでマーク化すると、付与済みの投稿もそのまま仕分けに使えます。投稿には1列に収まるマークを表示し、残りは「…」から名前で検索して選べます。管理ページの上下ボタンで投稿とサイドバーの順番を変更できます。投稿のアイコンをクリックすると即保存し、もう一度クリックすると解除します。マーク名をサイドバーで押すとその分類を開けます。「あとで読む」の下の「マークなし」では、名前付きマークが付いていない投稿をまとめて確認できます。通常タグ付きの投稿も対象です。「タグに戻す」はアイコンを外すだけで、投稿との関連は保持します。

従来のお気に入り状態も保存・JSONに保持しています。登録済みの場合は「以前のお気に入り」フィルタで閲覧できます。新しい仕分け操作はマークを使います。

## ビルドしてChromeへ読み込む

開発にはNode.js 22.12以上とnpmを使用します。

```sh
npm ci
npm run check
```

Chromeの `chrome://extensions` で開発者モードを有効にし、**生成された `dist` フォルダ**を「パッケージ化されていない拡張機能を読み込む」から選択します。ビルド後の利用にNode.jsやlocalhostサーバーは不要です。

Xにログインして [History](https://x.com/i/history) の **Bookmarks（ブックマーク）** を選び、拡張アイコンを押します。従来の `/i/bookmarks` にも対応します。Likesは取り込み対象にしません。対象アカウントと設定を確認して「少量ずつ自動取り込み」を押してください。Xのタブを表示したまま使います。タブの切替、移動、取得制限等を検出した場合は停止します。管理画面は拡張の「ライブラリを開く」から開けます。

既存の拡張を更新する場合は、同じ `dist` を使い、`chrome://extensions` のxbookmarkshelfの再読み込みを押します。その後、Xと管理画面のタブも再読み込みしてください。

## 配布とライセンス

配布するのはビルド済みの `dist` 内だけです。xbookmarkshelfの製品コードには [MITライセンス](public/LICENSE.txt) を適用し、ビルド時に `dist/LICENSE.txt` として同梱します。著作権表記は `2026 xbookmarkshelf contributors` です。Preact（MIT）とDexie（Apache 2.0）は、それぞれの [ライセンス・NOTICE](public/THIRD_PARTY_NOTICES.txt) を `dist/THIRD_PARTY_NOTICES.txt` に保持します。

開発用のスキル、内部資料、テスト、ツール、実データは拡張の配布物に含めません。

## 開発と検証

`npm run check` で型チェック・単体テスト・製品ビルドを実行します。ブラウザーテストは、ビルド後に以下を実行します。

```sh
npm exec playwright install chromium
npm run test:browser
```

自動試験は合成DOMとテスト用DBを使い、Xへの実通信を含めません。`npm run dev` は開発用の管理画面サーバーです。取得方式の実装は、規約適合性・必要な許諾・全件取得の確認済みという意味では扱いません。

## Gitで管理する範囲

製品コード、テスト、ビルド設定、依存ロックファイル、このREADME、製品と依存のライセンスを管理します。[.gitignore](.gitignore) で、開発用スキル・AI設定・内部文書・作業メモ・生成物・秘密情報・実データを除外します。内部文書はローカルに保持し、公開する説明はこのREADMEに置きます。

ルートのMarkdownはREADME・CHANGELOG・CONTRIBUTING・SECURITY・LICENSEだけを管理対象にできます。手元のメモは `notes/` または `memos/`、実データは `local-data/` または `private/` に保存してください。バックアップJSONは `backups/`、書き出したファイルは `exports/` に保管できます。
